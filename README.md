# DNS キャッシュのひみつ

「DNS浸透」と呼ばれる現象を、DNS とブラウザーのキャッシュを操作しながら学ぶ Web ツールです。アドレス（A / AAAA）の変更と権威サーバーの移転を切り替えて、アクセス結果やキャッシュの残り時間、問い合わせの流れを確認できます。

これはブラウザー内で完結する**シミュレーション**です。実際の DNS サーバーへの問い合わせや設定の変更は行いません。

## 起動

Node.js 18 以降が必要です。外部パッケージのインストールやビルドは不要です。FreeBSD では、必要に応じて Node.js と npm をパッケージからインストールしてください。

```sh
pkg install node npm
npm start
```

既定では `127.0.0.1:3000` で HTTP を待ち受けます。変更する場合は `HOST` と `PORT` を指定します。

```sh
HOST=127.0.0.1 PORT=3000 npm start
```

ブラウザーで `http://127.0.0.1:3000/` にアクセスします。別ホストから公開する場合は Node.js をループバックで待ち受けさせ、別途用意した Nginx で HTTPS を終端してください。例えば、証明書とドメインを用意したうえで、Nginx の HTTPS `server` ブロックに以下を設定します。

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## 使い方

1. シナリオとレコードタイプを選び、「サイトにアクセス」で各キャッシュを作ります。
2. 「設定を変更する」を押して再度アクセスすると、古いキャッシュが使われる様子を確認できます。
3. 時間を進めてアクセスを繰り返します。「HTTP キャッシュのみ消去」でブラウザーの DNS キャッシュを、「ブラウザーのキャッシュを消去」でリゾルバのキャッシュを確認できます。リセットすると選択中のシナリオを最初から試せます。

デモではアドレスの TTL を 120 秒、委任先を 180 秒、ブラウザーの DNS キャッシュを 30 秒、HTTP キャッシュを 90 秒に固定しています。HTTP キャッシュが有効な間は DNS 問い合わせを行いません。権威サーバー移転のシナリオでは、旧サーバーが古い答えを返し続ける場合をモデル化しています。古い委任先から再取得したアドレスは、委任先の期限が切れた後も自身の TTL まで残ります。

実際のブラウザーやリゾルバのキャッシュ、接続再利用、TTL の扱いは実装や設定によって異なります。このデモは DNS のすべての挙動を再現するものではありません。移転時には旧・新サーバーのデータの整合性や、親ゾーンの委任・グルーも考慮してください。
