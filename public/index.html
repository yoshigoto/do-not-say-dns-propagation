THE DNS MISCONCEPTION 01 / 02

「DNS浸透」ではなく
キャッシュの更新。

設定変更がインターネット全体へ一斉に伝わるわけではありません。
設定を変更する前に行われた Web アクセスをトリガーとする DNS や HTTP の応答は各キャッシュに残り、それらは各キャッシュの TTL に従って期限切れになるまで利用され続けます。
重要なのは、設定を変更した後に Web アクセスを行うことです。これにより、不要なキャッシュの影響を避け、新しい設定に基づく応答を取得できます。

03 何が起きた？

アクティビティ / ACTIVITY LOG

● LIVE

    このデモのしくみ / BEHIND THE SCENES

    01 / フルサービスリゾルバーのキャッシュIP アドレスのリソースレコードの TTL は 120 秒、委任情報の TTL は 180 秒。委任情報が古いと、IP アドレスを再取得しても旧権威サーバーから古い応答を受け取ることがあります。このデモでは NS リソースレコードによる委任とグルーレコードを 1 つのキャッシュとして簡略化しています。

    02 / ブラウザーのキャッシュブラウザーはドメイン名自体ではなく、名前解決で得た IP アドレスをキャッシュする場合があります。このモデルでは DNS の応答を 30 秒間、HTTP のページを 90 秒間保存します。HTTP キャッシュが有効なら DNS に問い合わせずページを表示します。実際にはブラウザー内部のキャッシュ、OS の DNS キャッシュ、接続再利用の挙動が重なり、保持時間も製品や設定によって異なります。ブラウザーのキャッシュを消去してもフルサービスリゾルバーのキャッシュは残います。

    03 / 実際の運用ではTTL やブラウザーのキャッシュ・接続再利用の挙動は製品や設定によって異なります。移転前に新サーバーのゾーンデータを整え、旧・新サーバーの応答を揃えましょう。親ゾーンの委任情報、必要なグルーレコード、各リソースレコードの TTL も考慮します。
